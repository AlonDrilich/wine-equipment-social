# Creative System — the postcard compositor

> The current creative standard (v6). Assets are **rendered in code**, not generated by an image
> model, so typography is exact, specs are ours, and nothing garbles. Generated photography is used
> only as a background layer. Renderer: [`postcard.py`](postcard.py) · library: `assets/cards-v6/`.

## Why it's built this way
Two review rounds killed the earlier approaches:
1. **Pure typographic posters** ("YOUR PRESS WILL FAIL…") read as quote cards — they talk to people
   who already know the category, and to everyone else they look like a consultancy.
2. **AI-rendered text cards** (ideogram) can't be trusted: it garbled "316L" into "3136L", and there
   is no control over type size — which is how the sub-line ended up unreadable on mobile.

So: **Pillow renders the type, flux supplies the photograph.** Exact control, zero garbling, and the
"spec that matters" numbers are real values from `brand/canonical-facts.md`.

## Run it
```bash
python3 media/postcard.py <spec.json> <outdir>
```
`spec.json` is a list of card objects; each needs `name`, `layout`, `headline`, `cta`.
Output: 1080×1350 (4:5) PNG per card.

## Layouts
| Layout | What it is | Needs |
|---|---|---|
| `hero` | Photo + big headline + large sub-line | `photo`, `sub` |
| `spec` | Photo + **the spec that matters, next to the price** | `photo`, `spec_label/value/note`, `price` |
| `compare` | Photo + output-per-hour bars | `photo`, `rows[{label,value,display,win}]` |
| `flow` | Photo + numbered process strip | `photo`, `steps[]` |
| `table` | **Reference table** — the save-worthy format | `cols[]`, `rows[[]]`, optional `photo`, `widths[]` |
| `tree` | **Decision tree** — root question → N branches with verdicts | `root`, `lanes[{cond,answer,bullets,verdict}]`, `footnote` |
| `versus` | Two ways to do the same thing, ours wins | `cols[{title,steps,outcome,outcome_label,win}]` |
| `dotgrid` | A year as dots, a few highlighted | `total`, `per_row`, `highlight[]`, `legend` |

**`table`, `tree`, `versus` and `dotgrid` need no photograph** — they're pure typography, so new ones
cost nothing to produce. That's the cheapest way to expand the library.

## Design rules baked into the renderer
- **Kicker chips** — the eyebrow sits on a solid green chip so it stays legible on a bright brass
  photo or a black cellar.
- **Sub-lines are large** (44px on `hero`) — the review found the old ones vanished on mobile.
- **Cells can't overflow their column** — `table` shrinks a cell's font until it fits its column
  bound. (Fixed a real collision: "Crusher-destemmer" ran into "8–12 weeks".)
- **Diagrams move as one unit** — `tree` draws root + connectors + lanes on a single layer, then
  centres it, so the connectors never detach.
- **Dots never merge** — `dotgrid` highlights are 1.25× radius, not 1.9×, or consecutive days blob.
- **Headlines auto-fit** — largest DIN size that wraps within the allowed line count.

## Type & colour
DIN Condensed Bold (headlines) · DIN Alternate Bold (numbers) · Arial Bold (body/labels).
Cream `#F5F1E9` · cellar-green `#1D3324` · gold `#C89B3C` · ink `#121A14`.

## The library (18 assets, v6)
Reference: tank sizing (ton→litres), six-stage number matrix, Italian spec-sheet decoder, lead-time
calendar, budget ladder, destemmer/bottling/pump sizing. Decision trees: filtration, 304-vs-316L,
new-vs-used. Versus: two ways to buy a tank / a press. Dotgrid: bottling days, crush weeks.
Offers: tell-us-your-tonnage, after-one-inquiry, go-direct-to-the-maker.
